# Porto Geofence Membership Changes

Given two consecutive taxi positions, which subscribed regions gained or lost the taxi? This correctness fixture pairs {{moves}} historical GPS updates from {{trips}} Porto trip prefixes with {{zones}} reproducible synthetic rectangles. You can test a geofencing engine, a spatial subscription router, or your own implementation against exact per-update labels.

**{{changed}}** updates change at least one membership. **{{unchanged}}** change none, including **{{stationary}}** stationary updates. Across the full replay there are **{{entered}}** entries and **{{exited}}** exits. The dataset fits in memory and has a single test split.

| File | Contents |
| --- | --- |
| `moves.jsonl.gz` | Gzip-compressed UTF-8 JSON Lines, one movement per line |
| `zones.json` | Array of 256 rectangles in zone-ID order, each given as `[xmin, ymin, xmax, ymax]` |

## Load and score a geofencing engine

```python
from datasets import load_dataset
from huggingface_hub import hf_hub_download
import json

repo = "pgg-engineering/edgechime-bench"
moves = load_dataset(repo, "porto-256", split="test")
with open(hf_hub_download(repo, "zones.json", repo_type="dataset")) as file:
    zones = json.load(file)

def predict(row):
    def contains(box, x, y):
        x_lo, y_lo, x_hi, y_hi = box
        return x_lo <= x < x_hi and y_lo <= y < y_hi

    old = {i for i, box in enumerate(zones) if contains(box, row["x0"], row["y0"])}
    new = {i for i, box in enumerate(zones) if contains(box, row["x1"], row["y1"])}
    return new - old, old - new

def exact_match(row):
    entered, exited = predict(row)
    return sorted(entered) == row["entered"] and sorted(exited) == row["exited"]

print(sum(map(exact_match, moves)) / len(moves))  # 1.0 for this reference
```

Replace `predict` with your engine. Return all callbacks, including repeats, when checking an event emitter. The scorer accepts any order and counts a row as correct only if both directions and their multiplicities match. For timing, build the index before replay and report build time, steady-state query time, and correctness separately. A local clone can read the split with Python's `gzip.open("moves.jsonl.gz", "rt")` and `json.loads(line)`.

## Schema and geometry

| Field | Meaning |
| --- | --- |
| `trip`, `step` | Zero-based trip ordinal in the selected sample and move ordinal within the trip. Each trip has its own sequence. |
| `x0`, `y0`, `x1`, `y1` | Previous and current longitude/latitude as signed integer microdegrees (WGS84). Divide each by 1,000,000 for degrees. |
| `prior_count` | Number of zones containing the previous position, including memberships retained at the next position. |
| `entered`, `exited` | Ascending lists of zero-based zone IDs whose membership changed between endpoints. |

A point belongs to a zone when both coordinates meet its lower bounds and are strictly below its upper bounds. A move that passes through a zone with both endpoints outside yields no event for that zone. The ordering of rows is trip-major, then chronological within trip.

## Provenance, generation and scope

The fixture takes the first 100 data records in file order from UCI's `Porto_taxi_data_test_partial_trajectories.csv`, retains records with `MISSING_DATA=False` and at least two positions, and rounds longitude and latitude to integer microdegrees. It retains all {{positions}} positions from the {{trips}} selected partial tracks, including repeated observations. The source describes a nominal 15-second sample cadence. Only coordinates and a new trip ordinal are published.

PGG Engineering generated overlapping subscriptions at three sizes. A 32-bit linear congruential generator starts at {{seed}}, selects observed positions uniformly with replacement, and draws independent half-widths and half-heights in integer microdegrees. For zone ID modulo three, the full ranges of possible half-extents are 250–499, 1,500–2,999, or 6,000–11,999 respectively. Every fourth box places an X edge at its sampled longitude, alternating left and right edges, to exercise boundary ties. Labels were generated by testing both endpoints against every rectangle. The exporter checks the full label stream against EdgeChime's index.

This fixture measures endpoint membership on one small nonrandom sample from one city. The rectangular zones are synthetic and depend on the sampled positions. The taxi source supplies movements only. Accuracy on this replay gives no production latency or accuracy guarantee for polygons, moving regions, or intermediate path crossings.

From the source archive, run `node bench/export-dataset.mjs ./porto-export` with Node 18+. The exporter uses the included trace. To regenerate the trace from UCI first, run `python3 bench/trace_porto.py`. SHA-256 of `zones.json` is `{{zones_sha256}}`. SHA-256 of the **decompressed** JSON Lines is `{{uncompressed_label_sha256}}`.
