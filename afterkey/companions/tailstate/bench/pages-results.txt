Synthetic workload. Every method replays the same shuffled dense-key input.
Build includes construction and initial inserts. Rewrites update 25% of keys,
including some deletes. Build order is randomized across five fresh stores.
Bytes requested include the store object/arrays, or the std::map object,
allocated tree nodes and dense key-to-iterator vector. Excludes allocator
metadata, benchmark inputs, and output arrays. These numbers do not measure RSS.

For each cohort, 256 requests resume from the middle half of the first load.
Current and overwritten anchor cohorts use adjacent initial sequence numbers.
Recent-window trials use this state. For older-window trials a single hot
key receives 65,536 additional rewrites. All query checkpoints are then outside
the revision ring. The warmup and timing still read the original checkpoints.
The final separate workload rewrites all keys in initial order, then rewrites
a consecutive run of five keys per block of 64, cycling its offset across the epoch. Its sampled recent cursors point at
those superseded anchors, and all four successor probes miss.
Writes finish before timing. Page requests return the first 16 full
ordered rows. Each method first warms its own working set. Method order and
cursor order are shuffled across five rounds. p50/p95 include read, digest
and timer overhead. An independent map traversal verifies every field before
timing; all methods in a cohort must also have identical timed digests.
These are warmed process-local reads, with no network, concurrency, or I/O.
