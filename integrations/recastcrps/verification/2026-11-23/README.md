# November 23 release verification

RecastCRPS 0.1.0 was checked against release commit 28be03c and default branch fee642c. The default branch also includes the withdrawal notebook. The public Space revision was 8b5a3d11d5fc3671c1d471a014b386570d320eee. With GCC 14.2 and CPython 3.12 on Linux x86-64, the anonymous archive build passed all nine Python tests. The native test passed. The native replay and the WebAssembly binary fetched from the live Space each agreed with direct pairwise CRPS for 3,844 updates. The native replay averaged 19.50197207 knots across 124 complete cycles. Browser interaction was unverified.

The [native drivers](../../bench/) ran once per scenario with all comparators, using GCC 14.2, C++17 and -O3 -DNDEBUG. The three CSVs named after their drivers contain these unpinned checks. A second withdrawal-extremes run used seven repetitions pinned to logical CPU 0 on an AMD EPYC 9V74. This repeats the release CPU model. For 4,096 changing members, the seven-run median was 199 ns per revision and extrema query versus 238 ns for ordered Fenwick. The unpinned single run reversed the order at 272 and 246 ns. On the pinned tie-heavy trace, ordered Fenwick led at 64 ns versus 108 ns. On the static trace, sorted prefix led at 64 ns versus 169 ns. See [all seven repetitions](extremes7.csv).

The [Python comparison protocol](../../comparison/) ran with its published dependencies, five trials, one thread and affinity to CPU 0. Its four ensemble sizes and both weight regimes passed the reference check. With eight equally weighted members, a prebuilt Numba batch took 70 ns per snapshot and RecastCRPS online took 273 ns. Separate individual weighted update-and-score timings on 8,192 members were 220 ns p50, 320 ns p95 and 430 ns p99 across 20,000 calls.
